01 / THE STUDYPaper DOI ↗

Beyond a
binary verdict.

A failed solution is more than a zero on a leaderboard.

We study code generated by DeepSeek-V3.1, Kimi-K2, Qwen-Plus, and Qwen3-Coder-Plus, including thinking-mode configurations for DeepSeek and Qwen-Plus. A shared taxonomy connects evaluator evidence across HumanEval, MBPP, and BigCodeBench.

Three complementary views separate complete correctness, the semantics of a failure, and its severity.

I

Does it pass?

Pass@1 measures whether one generated solution passes every official test.

correctness
II

What goes wrong?

Twenty subtypes describe observed failure semantics across three evaluator categories.

failure semantics
III

How much fails?

Macro and micro error ratios measure the share of failed tests among failed tasks.

conditional severity

04 / WHAT WE LEARNLOOK PAST THE LEADERBOARD

A pass rate cannot
tell the whole story.

01

Semantics remain
the bottleneck.

Equality and inequality failures (A_EQ_NEQ) are a central failure pattern across the study’s benchmarks and model configurations. Syntactically valid code can still miss the intended behavior.

02

Thinking changes
the shape of failure.

On BCB Hard, DeepSeek thinking-mode pass@1 decreases from 0.304 to 0.284, while its micro error ratio among failed tasks decreases slightly from 0.514 to 0.512. Correctness and conditional severity can move differently.

03

A shared language
makes comparison possible.

The same 20 subtypes connect evaluator-specific evidence. EvalPlus’s WrongAnswer and BigCodeBench’s AssertionError map to the same nine assertion subtypes.

READING THE ERROR RATIOS

Failed tasks are
the denominator.

Macro averages each failed task’s fraction of failing tests, giving tasks equal weight.

Micro pools failing tests across failed tasks, weighting tasks by their test counts.

Both are conditional severity measures. Neither is the overall task failure rate. See Table 3 and metric definitions ↗.
